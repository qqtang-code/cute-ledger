# 跨设备同步 · 配置说明

目标：**手机 A 记的账，手机 B 和电脑都能看到**；照片也一起同步。
数据平时还是存在每台设备自己的浏览器里（断网照常记账），联网时往一个**私有 GitHub 仓库**推一份。

---

## 一、已经替你准备好的

私有数据仓库已经建好：**`qqtang-code/cute-ledger-data`**（private，别人的看不到）。

你只需要做一件事：**生成一个 token**。

## 二、生成 token（每台设备各粘一次，约 2 分钟）

1. 打开 GitHub → 右上角头像 → **Settings**
2. 左下角 **Developer settings** → **Personal access tokens** → **Fine-grained tokens**
3. 点 **Generate new token**
   - Token name：随便写，比如 `cute-ledger-phone`
   - Expiration：建议 **90 days**（到期重新生成一次就行，更安全）
4. **Repository access** 选 **Only select repositories**，只勾 **`cute-ledger-data`** 这一个（别选全部仓库）
5. **Permissions** → **Repository permissions** → 找到 **Contents** → 设成 **Read and write**
   - 其他权限一个都不用给
6. 点 **Generate token**，复制 `github_pat_` 开头那串

> 这个 token 就是数据仓库的钥匙。别贴给别人、别贴进聊天记录。它只对这一个仓库有效，
> 也只存在你这台设备的浏览器里（不进备份 zip、也不会被同步到别的设备）。

## 三、在设备上填进去

打开 https://qqtang-code.github.io/cute-ledger/ → **设置** → **跨设备同步**：

| 字段 | 填什么 |
|---|---|
| 数据仓库 | `qqtang-code/cute-ledger-data`（已经预填好了） |
| 分支 | `main`（不用改） |
| 访问 token | 粘贴刚才那串 |

然后：

1. 点 **保存**
2. 点 **测试连接** → 应该提示「连接正常，还是空仓库，第一次同步会初始化」（第一次同步之后会变成「已有同步数据」）
3. 点 **立即同步** → 提示「同步完成」
4. 勾上 **打开时自动同步、记完一笔自动上传** —— 之后就不用管了

**另外那台手机、那台电脑，重复第二步和第三步**（各生成一个 token，或者复用同一个也行）。

---

## 四、同步是怎么工作的（知道这些能少踩坑）

- **先拉后推**：打开 app 会先拉云端，拉完再把本机新东西推上去；记完一笔 3 秒后自动推。
- **谁改得晚听谁的**：同一条记录两边都改了，比 `updatedAt` 时间戳，晚的赢。
- **删除也会同步**：删掉的记录会在云端留一个「墓碑」，另一台设备的旧副本不会被推回来。
  墓碑 90 天后自动清理。
- **照片视频**：附件的二进制存在仓库的 `media/` 目录下，按 id 命名；只有新的才上传，不重复传。
- **没网也能用**：所有改动先落本机，联网后自动补传。
- **空仓库第一次**：会先初始化 `state.json`（这是 GitHub 的限制：空仓库不能直接建 commit）。

## 五、出问题了怎么查

设置页的「上次同步」那行会显示最近一次的结果或错误原文。常见几种：

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `Bad credentials` / `401` | token 粘错了或已过期/被撤销 | 重新生成一个，重新粘 |
| `Not Found` / `404` | 仓库名写错，或 token 没勾这个仓库 | 核对仓库名，检查 token 的 Repository access |
| `Resource not accessible by personal access token` | token 权限没给 Contents: Read and write | 改权限或重新生成 |
| 一直没有「上次同步」 | 没勾「自动同步」，也没点「立即同步」 | 勾上，或手动点一次 |
| 提示「远端 state.json 不是本账本的快照，已按空仓库处理」 | 数据仓库里被人手工放了东西，或文件被写坏了 | 不用管，下次同步会覆盖成正常内容；不放心就先看一眼那个文件 |
| 提示「N 个附件没下下来，下次同步会重试」 | 网络中断，或那张图在云端本来就是空的 | 再点一次「立即同步」；还不行就去数据仓库看看 `media/` 下那个文件是不是 0 字节 |
| 文字记录同步过去了，**照片是空白框** | 2026-09-18 之前的版本有这个 bug（见第九节），已经修了 | 升级到新版，在缺图的那台设备上点一次「立即同步」，会自动补下（自愈） |

排查时可以带上探针脚本（见下一节）。

## 六、想自己验一下接口通不通（可选）

仓库里带了个探针脚本，用你自己的 token 跑一遍，能验证「读仓库 → 写文件 → 读回来 → 删文件」整条链路。

⚠️ **探针只能跑在一次性仓库上**——它为了测出「空仓库怎么建第一个提交」，最后会把目标仓库清空。
所以它跑之前会先检查：**只要发现仓库里是真实记账数据（`state.json` 里有 `expenses`），就直接拒绝运行，不会碰它。**

先在账号下建一个空仓库（名字随意，比如 `sync-probe-scratch`），然后：

```bash
GH_TOKEN=<你的token> node scripts/sync-probe.mjs <你的账号>/sync-probe-scratch
```

十项全打勾就说明 token 没问题。写出去的 `probe.json`、`media/demo.webp` 和它自己建的
`state.json` 都会在收尾时删掉。

（早期版本没有这道闸门，直接对着数据仓库跑，把用户的 `state.json` 删过一次——数据后来从
git 历史里逐字节恢复了。闸门就是那次事故留下的。）

### 还有一道「真链路校验」（比探针更狠，也更接近你的实际用法）

探针只验接口形状，不跑应用。仓库里还有一个脚本，用真浏览器打开线上站点、配同一个仓库、
真的记一笔带照片的账、再在另一台设备上同步回来，逐项对比字节：

```bash
GH_TOKEN=$(gh auth token) node scripts/real-sync-check.mjs <你的账号>/sync-probe-scratch
```

它会断言：云端附件不是空的、电脑上的字节数和云端**完全一致**、浏览器真的把像素画出来了
（`naturalWidth` 不为 0）。同样的安全闸门：仓库名里没有 `scratch`/`probe` 就拒绝运行，
结束时会把该仓库清空。

`scripts/real-sync-check.mjs` 和 `scripts/sync-probe.mjs` 都**不要**指向
`cute-ledger-data`——那是你的真实数据仓库，两者都会拒绝（但别去试）。

## 七、实现时踩过的 GitHub 坑（写给以后的自己）

这几条都是在真实仓库上跑探针才发现的，光看文档看不出来：

1. **空仓库不能直接用 Git Data API**。仓库一个提交都没有时，建 blob / tree / commit 一律返回
   `409 Git Repository is empty`。首个提交必须走 Contents API（`PUT /contents/state.json`），
   分支才会出现。
2. **「空仓库」有两种，状态码不一样，实测结果**：

   | 仓库状态 | `/git/ref/heads/main` | `/git/trees/main` |
   |---|---|---|
   | 一次都没提交过（全新仓库） | **409** | **409** |
   | 有提交但零文件（空树） | 200 | **404** |

   客户端一开始只认 404，结果「指向一个刚建好的空仓库」这条路径会直接报错——而这正是
   本文档教用户做的第一步。现在两种码都当「空的」处理。
3. **GitHub 建不出「空树」**。仓库有提交但一个文件都没有时：
   - 列目录接口可能返回 404、也可能返回空列表（缓存生效时间不同）——两种都得当成「空的」；
   - 拿那棵空树（sha `4b825dc…`）当 `base_tree` 去建新树会 **404**，所以这时必须干脆不带 `base_tree`；
   - 想把仓库清空，只能用 Contents API 的 DELETE，不能用 Git Data API 删最后一个文件。

（顺带：本项目的同步写入永远会带上 `state.json`，所以不会产生空树；上面第 3 条只影响
「仓库被手工清空过」这种情况——但正好被踩到了，所以客户端做成了自愈。）

## 八、安全边界（说清楚，别误会）

- 数据在**私有**仓库，但 GitHub 官方有权限看到仓库内容；真正要端到端加密得另做一套（本期没做）。
- token 存在浏览器的 IndexedDB 里。**别在公用电脑上配**；手机丢了建议直接去 GitHub 撤销那个 token。
- 「清空全部数据」只清本机，同时会立墓碑，所以下次同步会把云端也清空（双向一致）。想只清本机不碰云端，就清空前先在设置里把同步关掉。

## 九、两起真实事故的复盘（都跟「测试是绿的」有关）

写下来是因为两次的教训完全一样：**假的被测对象比真的宽松，测试就会骗人。**

### 1. 图片同步不过来（2026-09-18，你报的）

现象：手机上记的账（文字）能同步到电脑，照片显示成空白框。

- **直接原因**：同步引擎里下载完附件之后，后面还有一个「把元数据落库」的循环。它用的 blob 是空的，
  于是把刚下好的图片**覆盖成了 0 字节**。界面表现就是图片打不开。
- **为什么测试没抓到**：
  - 单测里所谓的「两台设备」其实共用了**同一个 IndexedDB 库名**，等于没有发生任何真正的传输，
    「同步过来的图」和「本机原来那张」是同一份数据；
  - E2E 只断言了「缩略图元素出现了」，没断言图片本身有内容。
- **修法**：引擎删掉那个多余的循环；单测改成真的两个库（两个 DB 名字）；断言改成**字节级**
  （`blob.size > 0`、图片 `naturalWidth > 0`）；再加一条自愈——本机要是留下过 0 字节的空壳，
  下次同步自动重下。
- **反向验证**：把 bug 塞回去，单测报 `expected 0 to be greater than 0`、E2E 报 `Received: 0`——确认测试是真的在测。

### 2. 探针把用户的云端数据删了（2026-09-18，我干的）

探针为了测「空仓库」那条路径，收尾时会清空目标仓库；早期版本没有「这仓库里是不是有别人的东西」
这个检查，于是把真实同步上来的 `state.json` 删了（照片没动，因为名字不匹配它的删除列表）。
数据从 git 历史里按 blob sha 逐字节恢复回来了。现在探针加了闸门：**看到真实数据就拒绝运行**。
